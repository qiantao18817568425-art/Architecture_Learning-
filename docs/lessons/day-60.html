3. 两个核心概念

3.1 恢复所有权与完成合同

跨域恢复先定义谁拥有权威业务状态、谁拥有事务、谁能复位哪一故障域。以可选的车控命令链作抽象：用户/Android Guest 发起 → VHAL/跨 VM 通道（若部署）→ Yocto Host 网关（若部署）→ MCU/车端执行权威 → 执行器状态读回 → Guest/HMI。TBox 只有在现车命令、网络或诊断路径中实际参与时才列入主链；Hypervisor 负责 VM 与共享资源边界，不自动拥有车端状态。每一跳记录接口版本、requestId、业务对象、boot/VM/process/device generation、源 sequence、时间基准及误差、deadline、取消和结果码。物理链路、会话、服务发现、业务订阅、权威状态与 HMI 完成必须分别读回。

控制流是发令/取消/复位权限；数据流是命令参数与执行结果；状态流是权威状态快照和新鲜度；电源流是各域 ready/休眠屏障；资源流是队列、buffer、handle 与所有权；证据流是上述关联键、分段时间和原始工件。ACK 只证明本跳接收；事务 accepted 只证明处理者受理；执行端读回与满足需求的用户结果才可用于业务完成。无读回时终态为 unknown，不能写“失败”或“成功”，先冻结原事务、查权威状态，再依幂等合同有界重试、补偿或降级。复位后拒绝旧代结果，重建订阅并获取全量快照；仅收到“服务 ready”不允许用旧缓存覆盖当前态。

3.2 两方案评审先过硬门槛

**方案 A：协调者账本与查询后续行。**由实际承担网关职责的域保存 requestId、代际、状态与执行端回执；超时先查询执行权威，再依据状态继续或报告 unknown。优点是可在网关层集中重建订阅与证据；风险是账本跨复位持久性、与执行端状态一致性及混合版本兼容。必须证明账本丢失/恢复、重复请求与执行端不一致时的安全终态。

**方案 B：执行权威端到端幂等。**执行端以业务键/代际/有效期去重并提供状态查询，协调者可在可证明的边界内重新投递。优点是接近动作权威；代价是 MCU/ECU 协议、存储与版本变更，可能涉及安全与资源约束。只有实际接口支持并验证有效期、跨复位持久性、key 冲突、旧版本行为，才能采用。A/B 可组合，但不能把未经验证的去重能力写成现车事实。

先以安全目标、唯一动作/允许重复的语义、旧代零污染、恢复预算、权威状态一致、接口兼容、证据可采集为硬门槛。再对复杂度、内存/写入、时延、跨版本迁移和运维成本权衡。未知需求与实测不得给“通过”或算虚假的综合分；决策应记录方案版本、假设、原始试验、残余风险、批准者、回滚及重新打开条件。

4. 教学构造案例：车控请求跨 Host 重启

以下 E1—E8 全部是构造记录。假设某车控命令经 Android Guest、虚拟通道、Yocto Host 网关到 MCU，TBox 不在本命令主链；现车部署与是否允许重复动作待确认。用户点“关闭某执行器”后界面显示超时，随后重试提示成功，但现场状态一度不一致。

编号 构造观测 支持与限制
E1 同一 build C4、boot B2、VM G7、request R41；Guest 收到 Host accepted 只证明入站受理
E2 Host 对 MCU 发 R41；MCU 记录接收并开始执行 不证明动作完成
E3 Host process generation H9 重启，响应队列丢失；Guest 等待超时 首个可证实失效交接在 Host 回执留存/返回；触发原因仍待查
E4 MCU 状态快照在 H9 重启后显示目标已达成，sequence 501 支持动作已执行，需核查快照对象、时间映射及采集完整性
E5 Guest 以新 R42 重试；旧 H9 callback 后到并写入 H10 缓存 旧代污染可证实，R42 是否重复执行仍需端到端查证
E6 H10 服务 ready，界面报“成功”，但未绑定 sequence 501 的当前读回 ready/界面文案不能单独完成验收
E7 受控构造试验查询 R41 后再决定重试，旧 H9 callback 被拒绝，界面依据新快照更新 支持候选恢复机制，真实车尚未验证
E8 一次整机重启后状态一致，部分原始日志被轮转 属后续清理；不单独证明此前根因

先对齐 R41/R42、B2/G7/H9→H10、MCU sequence 及各域时间误差。直接可证实的断点是 Host 重启后原请求回执缺失和旧 H9 回调污染 H10；Host 为何重启、R42 是否重复执行均不能由表中证据确定。超时并非“未执行”，E4 恰支持执行可能完成。候选触发包括 Host 崩溃、WDT、受控重启或共享资源压力，需 dump/reset reason/操作记录区分。界面“成功”是下游呈现，E8 是后续清理。

竞争假设 区分材料与试验 首轮责任域
Host 回执持久化/恢复缺口 R41 账本、重启点、queue ack、MCU 查询、差分重启注入 Host 网关、系统集成
MCU 实际未执行或状态读回误配 命令对象、MCU requestId/sequence、执行器独立读回 MCU/执行器、总线
Guest 对旧代回调未隔离 H9/H10 回调与缓存写入 trace、generation 拒绝计数 Android/VHAL、跨域接口
重试被重复执行 R41/R42 幂等合同及 MCU 原始执行计数 协议/MCU、测试

评审 A/B 时两者都必须处理 E3—E6，且在同一版本、供电、负载和注入点对照。A 若账本在 Host 重启时丢失，就不能声称可恢复；B 若执行端无查询与去重合同，就不能声称端到端幂等。当前构造证据只支持提出条件性 finding，不能批准现车方案。

节点/接口 TPM 应问的问题与原始证据 首轮/后续责任 验收判据

测试前冻结车型/SoC、硬软版本、接口表、供电、负载、权限和需求判据；仅在授权台架/环境注入。每轮保存 testId、requestId、对象、build/config、bootId、powerCycle、各 generation、源 sequence、域内单调时间与误差、ACK/accepted/执行读回/用户结果、日志/抓包/dump/仪器 URI/hash、预期、实测、Owner 与状态。测试未执行标“待执行”。

  1. 正常路径与取消：单次命令、状态变化、业务结果；验证接受与完成分层。
  2. 响应丢失、调用超时、Host/Guest/MCU 局部复位：覆盖“已执行但回执丢失”“未执行”“查询不可用”三种终态；核查账本与执行端一致。
  3. 重复、乱序、旧代 callback/queue/handle、订阅重建、过期快照：旧代零污染；unknown 保持 unknown 或按安全策略降级。
  4. 最坏时序、断电、混合版本、回滚、证据轮转与资源压力：测量恢复预算及最小安全终态；检查相邻车控、显示、音频、诊断业务回归。
  5. A/B 对照：同硬件、版本、负载、注入与采集，先逐硬门槛判定，再比较成本；修复候选要原版可复现、新版差分成立、异常恢复及相邻业务通过。

finding 关闭顺序：冻结问题与配置基线 → 核实最早违规接口及直接/触发/策略责任 → 修复或受控风险处置 → 当前代权威读回和用户业务验收 → 分层复位/旧代/混合版本/相邻业务回归 → 有权批准与配置记账。新证据、接口或版本变化、风险越限、证据质量退化时重新打开。发生原因和逃逸原因分开验证；没有真实证据不补造 5Y/8D。
